# Plan: code quality and reliability corrections

> **For the implementer:** execute this plan through delegated agents, one
> write scope at a time when scopes overlap. Preserve all pre-existing dirty
> changes in the checkout.

**Goal:** corrigir os achados de segurança, confiabilidade e qualidade de
código da auditoria Luna, mantendo os contratos de ownership de notas/tasks.

**Design:** `docs/superpowers/specs/2026-09-16-code-quality-reliability-corrections-design.md`.

**Verification:** testes focados por lote, `go test ./...`, `go vet ./...`,
`flutter analyze --no-pub` e `git diff --check`, conforme disponibilidade do
ambiente.

## Work packages and disjoint write sets

### 1. Backend runtime, configuration and Alexa

**Files:** `backend/cmd/server/main.go`, `backend/pkg/config/**`,
`backend/internal/alexa/**` and their focused tests.

- Remove/protect debug exposure.
- Make unsafe configuration fail closed and add tests for missing production
  secrets/environment.
- Validate Alexa request authenticity, timestamp and idempotency before
  business logic.
- Keep handlers thin and preserve existing local development ergonomics only
  behind explicit development configuration.

### 2. Backend attachments and storage lifecycle

**Files:** `backend/internal/attachments/**`,
`backend/db/queries/attachments.sql`, generated attachment files only when
regenerated by the project tool, and focused tests.

- Fix upload response contract and error propagation.
- Make orphan cleanup/deletion safe under retries and references.
- Add rollback/idempotence coverage without visual tests.

### 3. Backend MCP, sharing intake and sensitive logging

**Files:** `backend/internal/mcp/**`, `backend/internal/shareintake/**`,
`backend/internal/sharelinks/**` only for logging/contract findings, and
focused tests.

- Default MCP to read-only and scope tool discovery.
- Make destructive confirmation atomic/recoverable/idempotent.
- Fix `reopen`, typed parsing, enum validation and `update_note` policy.
- Redact share URLs/tokens from logs.

### 4. Backend task/note/auth domain boundaries

**Files:** `backend/internal/tasks/**`, the specific files under
`backend/internal/noteoperations/**`, `backend/internal/auth/service.go`,
`backend/internal/notes/handler.go`, plus focused tests.

- Split oversized task service responsibilities into small typed operations
  without introducing a generic domain framework.
- Make document mutation strict; recovery belongs to explicit bootstrap paths.
- Centralize recurrence/reminder semantics and preserve task ownership.
- Propagate invalid session/cursor inputs instead of discarding errors.
- Keep SQLC behind the narrowest useful repository/API boundary.

### 5. Flutter auth and session lifecycle

**Files:** `lib/core/api/auth_interceptor.dart`,
`lib/core/auth/auth_tokens.dart`, `lib/features/auth/data/auth_local_storage.dart`,
`lib/features/auth/presentation/controllers/auth_controller.dart`, related
focused tests.

- Consolidate token pair and refresh contracts.
- Make new token format parsing explicit and fallback only when the new record
  is absent, not malformed.
- Extract deterministic session cleanup from the controller while preserving
  all resource disposal and error reporting.

### 6. Flutter editor, codec and attachments

**Files:** `lib/features/notes/editor/application/**`,
`lib/features/notes/editor/document/**` excluding sync files,
`lib/features/notes/editor/presentation/**`,
`lib/features/notes/attachments/**`, `notes_repository.dart` only if needed for
the data/presentation dependency, and corresponding focused tests.

- Separate pure editor diff/domain commands from listeners/controllers.
- Make codec boundaries real or keep a single cohesive codec; do not preserve
  a cosmetic `part`/mixin split.
- Remove optional upload no-op behavior and type the upload response.
- Keep business logic out of widgets and follow existing shared components.

### 7. Flutter tasks, recurrence, preferences and sharing controllers

**Files:** `lib/features/tasks/**`,
`lib/features/notes/preferences/**`,
`lib/features/notes/sharing/application/share_note_controller.dart`,
related focused tests.

- Remove duplicate request state and callback soup.
- Move metadata sheet to draft-in/return-draft semantics; owner persists and
  requests permission.
- Centralize recurrence/occurrence decisions and expose blocked diagnostics.
- Deduplicate share mutation execution and protect stale operations.

### 8. Flutter sync, catalog and database

**Files:** `lib/core/sync/**`, `lib/core/database/daos/note_operations_dao.dart`,
`lib/core/database/**` only for the required migration/schema contract,
`lib/features/notes/catalog/data/**`, and corresponding focused tests.

- Split sync response handling into typed reconcile/persistence units.
- Make projection failure visible and atomic.
- Establish one owner of per-note ordering and simplify the remote coordinator.
- Remove optional callbacks/flags and duplicate session gate logic.
- Use set-based DAO mutations and validate operation ID/payload reuse.

### 9. Documentation and final code hygiene

**Files:** only documentation and clearly dead files identified after packages
1–8; no broad formatting or unrelated rewrites.

- Align ownership/API docs with runtime.
- Remove confirmed dead APIs/callbacks/helpers.
- Run reference search for removed symbols and document known intentional
  historical references.

## Integration procedure

1. Before each agent starts, record `git status --short` and tell it to
   preserve unrelated changes.
2. Agents edit only their listed write set, add focused regression tests, and
   report files changed plus commands run.
3. After each package, inspect `git diff --stat`, `git diff --check` and any
   generated-code changes before starting a dependent package.
4. Do not accept a refactor that only renames/moves code while preserving the
   same callback/flag complexity; ask the agent to simplify the boundary.
5. After all packages, run the Sol low validation pass against the original
   findings and the aggregate diff.
